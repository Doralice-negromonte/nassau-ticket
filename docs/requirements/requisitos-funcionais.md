1\. Requisitos Funcionais

| CÓDIGO | DESCRIÇÃO | PRIORIDADE |
| :---- | :---- | :---- |
| RF01 | O sistema deve permitir que o cliente emita uma senha por meio do totem, sem necessidade de identificação. | alta |
| RF02 | O sistema deve gerar automaticamente o número da senha no formato: YYMMDD-PPSQ | alta |
| RF03 | O atendente deve poder solicitar a próxima senha. O sistema deve selecionar automaticamente a senha seguindo as regras de prioridade.  | alta |
| RF04 | O sistema deve possuir um painel de chamadas mostrando as 5 últimas senhas chamadas. | alta |
| RF05 | Depois que o cliente chegar ao guichê, o atendente deve poder iniciar o atendimento.  | alta |
| RF06  | O atendente deve poder finalizar o atendimento após sua conclusão. | alta |
| RF07 | O sistema deve permitir que o atendente chame novamente uma senha quando o cliente não comparecer.  | media |
| RF08 | Caso o cliente não compareça após as chamadas previstas, o sistema deve registrar a senha como NÃO\_COMPARECEU.  | media |
| RF09 | O sistema deve possuir autenticação para o atendente.  | alta |
| RF10 | O sistema deve permitir que um atendente possua perfil adicional de gestor, responsável pelos cadastros e relatórios.  | alta |
| RF11 | O gestor deve poder realizar os cadastros necessários ao sistema. | alta |
| RF12 | O sistema deve gerar relatório diário | alta |
| RF13 | O sistema deve disponibilizar os mesmos indicadores em período mensal.  | media |
| RF14 | O sistema deve gerar relatórios detalhado de senhas mantendo vazio os campos de atendimento para as senhas não atendidas | alta |
| RF15  | O sistema deve disponibilizar o tempo médio de atendimento.  | media |
| RF16  | O sistema deve gerar um relatório de auditoria | alta |
| RF17 | O sistema deve controlar o estado de cada senha | alta |
| RF18 | O sistema deve considerar a chamada por áudio | baixa |
